# Building Research Center Section

## When to use this skill
- User uploads a new research PDF and asks to generate the research-center HTML into an existing file
- User says "create/update the research center section" for a new report
- User provides a `long-description.html` file that contains boilerplates and asks you to add the research-center block.

---

## Context: What is the Research Center?

The **Research Center** is the core scrollable section of every HR.com research report landing page. It replicates the full PDF content as HTML — chapters, text, charts, callouts — giving the user the full reading experience in-page.

The page is built in a CMS. The HTML goes into the CMS as the `$desc_long` field. It must be **self-contained** — no external build tools. CSS is loaded via `$public/remoteimages/research/css/research-webview-styles-v5.css` and JS via `$public/remoteimages/research/css/research-webview-script-v4.js`.

> ⚠️ The `<link>` stylesheet tag at the top of the file is for **local preview only**. It should be commented out before handing off to the CMS. The user will manage this toggle. Do NOT touch it.

## Approach: Chapter-by-Chapter Workflow

> **IMPORTANT**: The user provides chapter PDFs one at a time. Do NOT build all chapters at once unless explicitly asked.

For each chapter the user provides:
1. Run `extract_pdf.js` on the chapter PDF immediately (always auto-run).
2. Wait for extraction, then read the full `chapter-N-extracted.txt`.
3. Build that single chapter's HTML and insert it into `long-description.html`.
4. Confirm completion and wait for the user to provide the next chapter PDF.

## Full Page Structure (long-description.html)

The entire file is a single `<div class="main-container">` containing these sections in order:

```
1. .hero-section             (DO NOT TOUCH)
2. .section > .research-center   ← ONLY FOCUS
3. .did-you-know               (DO NOT TOUCH)
4. .advisory-board             (DO NOT TOUCH)
5. .sponsors-section           (DO NOT TOUCH)
6. .cta section                (DO NOT TOUCH)
7. <script> (advisory board JS) (DO NOT TOUCH)
```

> ⚠️ **CRITICAL RULE**: This skill is strictly for building and updating the `.research-center` block. You MUST NOT modify, add, or delete content in any other section of the file (Hero, Did You Know, Advisory Board, Sponsors, CTA). Any request to update those sections must be handled separately or by a different skill.

### The `.research-center` block

```html
<section class="section">
  <div class="section-center research-center">
    <div class="research-container">

      <!-- LEFT: Sidebar / Table of Contents -->
      <div class="research-sidebar" id="sidebar">
        <div class="toc-title">
          <h2 class="heading-2">Table of Contents</h2>
          <button class="toc-button button" onclick="toggleSidebar()">Expand</button>
        </div>
        <div class="nav-container" id="toc-container">
          <a href="#chapter-1"><i class="fas fa-circle"></i> Chapter Title</a>
          <a href="#chapter-2"><i class="fas fa-circle"></i> Chapter Title</a>
          <!-- one <a> per chapter -->
        </div>
      </div>

      <!-- RIGHT: Scrollable content pane -->
      <div class="research-content-container">
        <div id="research-content">
          <!-- chapter-1 through chapter-N -->

          <!-- ======================================================================================== -->
        </div>
      </div>

    </div>
  </div>
</section>
```

> ⚠️ **Separator comment**: Each new chapter is inserted **before** the `<!-- ======================== -->` separator. Do NOT delete or move that comment.

## Chapter 1 (Executive Summary) Pattern

Chapter 1 ALWAYS starts with the full report title (`hero-title`) followed by the chapter heading:

```html
<div class="chapter-container" id="chapter-1">
  <h2 class="hero-title">
    HR.com's State of [Report Topic] [Year]
  </h2>

  <h2 class="chapter-title">Executive Summary</h2>

  <!-- Intro paragraphs verbatim from PDF -->
  <p>...</p>

  <!-- About the Survey highlight box -->
  <div class="highlight">
    <h3>About the Survey</h3>
    <p>Survey date range, respondent count, demographics...</p>
    <p>Employer size breakdown...</p>
  </div>

  <!-- Defining [Key Term] highlight box (if present in PDF) -->
  <div class="highlight">
    <h3>Defining [Key Term]</h3>
    <p>Definition provided to survey respondents...</p>
  </div>

  <!-- Major Research Findings sub-heading -->
  <h3 class="chapter-subtitle">Major Research Findings</h3>

  <!-- One .major-finding block per numbered finding -->
  <div class="major-finding">
    <p>1. Finding statement verbatim...</p>
    <ul class="research-list">
      <li>Bullet stat</li>
      <li>Bullet stat</li>
    </ul>
  </div>

  <!-- Legal disclaimer footnote AFTER the last major finding -->
  <p class="research-note">
    <i>Please note that the findings and recommendations contained in this report are informational only.
    Nothing in this report should be construed as constituting legal opinions or advice. Please consult an
    attorney if you have questions about the legal requirements, rules, or regulations associated with any
    content discussed in this report.</i>
  </p>

</div><!-- end chapter-1 -->
```

## Chapter 2+ Pattern (Standard Chapters)

```html
<div class="chapter-container" id="chapter-N">
  <h2 class="chapter-title">Chapter Title from PDF</h2>

  <!-- Optional intro paragraphs -->
  <p>Intro text copied verbatim from PDF...</p>

  <!-- Finding block (repeats for each finding in the chapter) -->
  <h3 class="research-finding">
    Finding: Exact finding text from PDF
  </h3>
  <p>Body paragraph text from PDF...</p>

  <!-- Chart image — use the simple chart-img class (see Chart Rules below) -->
  <img alt="Verbatim chart title from PDF" class="chart-img"
    src="https://public-cdn.hr.com/remoteimages/research/images/[report-slug]/chart-N.webp" />

  <!-- Chi-square test highlight (if present in PDF) -->
  <div class="highlight">
    <h3>Results of Chi-square test</h3>
    <p>A chi-square test of independence shows that...</p>
  </div>

  <!-- Cohort definition highlight (if present in PDF) -->
  <div class="highlight">
    <h3>[Cohort Name] cohort classification</h3>
    <p>Definition intro text...</p>
    <ul class="research-list">
      <li><strong>Leaders:</strong> definition...</li>
      <li><strong>Laggards:</strong> definition...</li>
    </ul>
    <p>Correlation note...</p>
  </div>

  <!-- Organizational size note (if present in PDF as a sidebar box) -->
  <!-- Place this AFTER the relevant body paragraph, BEFORE the chart it relates to -->
  <div class="highlight side-note">
    <h3>Differences by organizational size</h3>
    <p>Large organizations (X%) are significantly more likely than midsized (Y%)...</p>
  </div>

  <!-- HRRI Strategic Recommendations (if present in PDF) -->
  <div class="highlight">
    <h3>HRRI Strategic Recommendations</h3>
    <p>Based on our research, please consider the following suggestions:</p>
    <ul class="research-list">
      <li>Recommendation text verbatim from PDF.</li>
    </ul>
  </div>

</div><!-- end chapter-N -->
```

```html
    <p><strong>Key Takeaway 2: Takeaway headline verbatim.</strong></p>
    <p>Supporting paragraph text verbatim from PDF...</p>
  </div>

</div><!-- end chapter-N -->
```

## CSS Classes Reference

| Class | Purpose |
|---|---|
| `.chapter-container` | Wraps one full chapter. Has a visual divider `::after` |
| `.hero-title` | `<h2>` used for the full report title at the top of Chapter 1 only |
| `.chapter-title` | `<h2>` chapter heading (also used for mid-chapter section pivots) |
| `.research-finding` | `<h3>` finding statement (include "Finding:" prefix verbatim) |
| `.chapter-subtitle` | `<h3>` used in Exec Summary for "Major Research Findings" sub-heading |
| `.research-list` | `<ul>` for bulleted research stats |
| `.research-sublist` | `<ul>` nested inside `.research-list` |
| `.major-finding` | Boxed finding block — used in Exec Summary AND Key Takeaways chapters |
| `.highlight` | Callout box — About the Survey, Cohort definitions, Chi-square tests, Strategic Recommendations |
| `.highlight.side-note` | Same as `.highlight` but for sidebar-style notes from the PDF (org size differences, etc.) |
| `.chart-img` | Class on the actual chart `<img>`. **This is the ONLY chart class to use.** |
| `.research-note` | Small-text footnote or disclaimer. Requires `!important` CSS overrides. |

## Chart Rules — CRITICAL

> ⚠️ **Use `class="chart-img"` ONLY. Do NOT use `.custom-chart-wrapper`, `.custom-chart-content`, `.custom-chart-img`, or download/share icon divs.**

The correct chart format is:

```html
<img alt="Verbatim chart question from PDF" class="chart-img"
  src="https://public-cdn.hr.com/remoteimages/research/images/[report-slug]/chart-N.webp" />
```

- The user provides the **base URL** via the report slug. Only the filename at the end changes: `chart-1.webp`, `chart-2.webp`, etc.
- **Editor's notes** below charts (e.g., "Those who responded 'don't know' were removed...") are **PART OF THE CHART IMAGE** — do NOT add them as separate HTML text.
- **Alt text** must be the verbatim chart question from the PDF.
- Chart numbers are **sequential across the whole report**, not per chapter. Continue numbering from wherever the previous chapter ended.
- A chapter with **no chart** (e.g., Key Takeaways) does not increment the chart counter.
- **Call-out text/Highlight boxes**: If the PDF contains highlight boxes or call-outs that are visually part of the chart in the provided screenshots/images, do NOT add them as separate HTML elements. Only add them if they are separate text blocks in the PDF that are not captured within the chart image.

---

## Text Content Rules — CRITICAL

> ⚠️ **NEVER alter, paraphrase, or summarize the report copy.** All paragraph text, bullet points, findings, and headings must be copied **verbatim** from the PDF. The only modifications allowed are HTML encoding of special characters (`&amp;`, `&lt;`, etc.).

- Chapter titles → `class="chapter-title"`
- Finding statements → `class="research-finding"` (include the "Finding:" prefix as-is)
- Paragraph text → `<p>…</p>` (no added summaries). **Never combine separate paragraphs from the PDF into one `<p>` tag, and never split a single paragraph into multiple. Maintain the exact paragraph structure shown in the source PDF.**
- Bullets → `<li>` inside `.research-list`

---

## Hyperlink Rules

If the PDF text references an external study, source, or named piece of research, wrap the relevant text in a placeholder `<a>` tag. The user will fill in the correct URL later:

```html
<a href="#" target="_blank" rel="noopener noreferrer">referenced text</a>
```

- **Do NOT open URLs or verify links** — the user manages all hyperlink destinations.
- **Named laws/acts** (e.g., SECURE Act 2.0) also get placeholder tags.
- Once the user edits a placeholder with a real URL, that pattern is locked in for that term — do not reset it.

## Section-Pivot Headings

When a single PDF chapter contains two clearly distinct sections with their own headings (e.g., Chapter 5 contains "Measuring the Success…" AND "Specific Financial Wellness Offerings"), use a new `<h2 class="chapter-title">` inside the same `chapter-container` to create a visual pivot. Do NOT create a new `chapter-container` for it unless the PDF explicitly starts a new numbered chapter.

```html
<div class="chapter-container" id="chapter-5">
  <h2 class="chapter-title">Measuring the Success of Financial Wellness Programs</h2>
  <!-- ... findings ... -->

  <!-- Section pivot: new major heading within same chapter div -->
  <h2 class="chapter-title">Specific Financial Wellness Offerings</h2>
  <!-- ... findings ... -->
</div>
```

## `.research-note` Class (Footnotes / Disclaimers)

Use after legal disclaimers and footnotes (e.g., the end of the Executive Summary after the last major finding).

```html
<p class="research-note">
  <i>Please note that the findings and recommendations contained in this report are informational only.
  Nothing in this report should be construed as constituting legal opinions or advice. Please consult an
  attorney if you have questions about the legal requirements, rules, or regulations associated with any
  content discussed in this report.</i>
</p>
```

CSS (add to per-report `<style>` block if not already in global stylesheet):
```css
.research-note {
  font-size: 0.85em !important;
  color: #666 !important;
  margin-top: 16px;
}
```

## Custom Elements / New Designs

If the source PDF contains any new elements or custom content blocks not covered by the standard HTML patterns, you must:
1. Design the new HTML element so it visually matches the existing theme and brand styles.
2. Place any required CSS for this element inside the `<style>` tag in the HTML file.
3. **CRITICAL**: Every single CSS property for a custom element MUST be marked with `!important` to prevent the CMS from overriding it.

## TOC Sidebar Checklist

After each chapter is added, update the sidebar TOC in `<div class="nav-container" id="toc-container">`:

```html
<a href="#chapter-N"><i class="fas fa-circle"></i> Chapter Title</a>
```

- TOC titles should match the `<h2 class="chapter-title">` of that chapter (or the first section heading for Chapter 1).
- If a chapter has a section pivot (two headings), only add ONE TOC entry pointing to `#chapter-N`.
